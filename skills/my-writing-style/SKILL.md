# 个人风格写作

做两件事：**用「我」的风格写文章**；**从「我」的修改里持续学风格**。本 skill 只住程序（流程 + 检查表），你的数据——风格库和文章——全部住在 `config.md` 配置的目录里，跟着项目走、进 git、跨会话生效。用户可以直接改风格库文件，也可以通过「复盘」让 skill 自己学。

## 铁律

1. **风格库以磁盘最新内容为准。** 用户随时可能直接编辑风格库目录（config.md 指向）下的文件，这是合法且推荐的进化方式。每次写作前重新 Read，绝不用记忆中的旧版本。
2. **写入风格库前必须经用户确认。** 复盘提炼出的规则先列出来给用户看，确认后才写入；用户明确说"直接学，不用问我"时才可跳过。追加规则用 Edit 局部插入，绝不整文件重写——重写会抹掉用户手写的内容。
3. **只学"怎么写"，不学"写什么"。** 风格库记句式、用词、结构、语气，不记事实和观点内容。任何文章里都不编造事实、数据、引用、截图。
4. **写作与审查分离。** 正文写作和去 AI 味审查必须由两个互不相通的子 agent 分别完成，细节见下一节。

## 子 agent 分工：写作者与审查者隔离

同一个上下文里自己写自己查，会为自己的选择找理由——"这处破折号有必要""这里的此外不算堆叠"，查不动是必然的。所以：

- **主 agent（加载本 skill 的你）= 编排者。** 读风格库、对齐需求、确认大纲、派发子 agent、验收文件、跑复盘和提炼。不亲手写正文。
- **写作子 agent。** 拿任务包（声纹/规则/平台文件 + 大纲 + 素材）写正文，按声纹模仿着写，不做自我审查，不读检查表——写作时满脑子"不能像 AI"会让文字变僵，去 AI 味是审查者的事。
- **审查子 agent。** 只拿初稿文件路径 + 风格库 + 检查表，以挑剔编辑的身份直接在文件上改稿。它看不到写作过程的任何讨论和理由，只看得到稿子本身。

派发规则：

1. 两步都用 Agent 工具（general-purpose 子 agent），prompt 必须自包含——子 agent 看不到本会话的任何内容。
2. 审查子 agent 的 prompt 里禁止出现写作子 agent 的解释、大纲讨论、任何"为什么这么写"。只给文件路径和验收标准。
3. 审查后主 agent 读回文件做验收（文件存在、无【待补】遗留、风格库引用完整），但不重新润色正文——那会把偏见带回来。
4. 环境没有 Agent 工具时才降级为主 agent 依次扮演：切换到审查角色前，必须重新 Read 稿件和全部风格文件，清空写作思路，只带检查表再进稿子。

## 结构与配置

skill 目录只住程序（流程与检查表），用户数据全部住在 config.md 配置的目录里：

```
<skill目录>/                 # 程序：可整目录发布/安装
├── SKILL.md                 # 本文件：配置说明 + 三大流程
├── config.example.md        # 配置模板：新环境复制为 config.md 再填
├── config.md                # 本机实际配置（不入库、不进发布）
├── references/
│   └── ai-tells-zh.md       # 中文去AI味检查表（审查子agent必读）
└── assets/
    └── style-template/      # 首次运行时复制到用户风格库目录的种子模板
```

两个数据目录（都由 `config.md` 指向，默认都在用户的写作项目里）：

```
<风格库目录>/                # 默认 D:\code\my-publish-article\style —— 声纹和规则住这里
├── voice.md                 # 核心声纹。全平台通用，用户最常改的文件
├── rules.md                 # 硬规则：内置底线 + 复盘学到的教训
└── platforms/
    ├── wechat.md            # 公众号适配（薄，只有平台差异）
    ├── zhihu.md             # 知乎适配
    └── tech.md              # 掘金/博客/V2EX 等技术社区适配

<文章根目录>/                # 默认 D:\code\my-publish-article\articles —— 文章和语料住这里
├── imported/                # 用户导入的旧文章（提炼语料）
└── <日期-主题>/
    ├── draft.md             # 工作稿（复盘对比用；永远不是提炼素材）
    └── final.md             # 定稿（复盘落盘；提炼语料）
```

**配置规则：** 每次会话先 Read `config.md` 再干活，所有目录以它为准、以磁盘最新内容为准。改两行配置即可整体迁移工作环境。扫描语料时排除 `draft*.md` 和 `README.md`——AI 写的初稿绝不能学成用户的风格。

**首次运行（新装环境）：** `config.md` 不存在 → 复制 `config.example.md` 为 `config.md`，问用户两个数据目录放哪（各给一个默认建议），创建目录后把 `assets/style-template/` 的内容复制进风格库目录。模板里 voice.md 的 status 是未初始化，之后正常走流程三提炼。config.md 已存在的环境直接跳过这段。

`voice.md` 的 frontmatter `status` 字段是整个系统的开关：

- `未初始化` → 写作前必须先走流程三（提炼），或请用户口述偏好初始化。
- `已初始化: 日期, 基于 N 篇样本` → 正常写作。

## 流程一：写文章

1. **读配置和风格库。** 先 Read `config.md` 拿到风格库目录和文章根目录，再 Read 风格库目录下的 `voice.md`、`rules.md`、`platforms/<平台>.md`。平台不在三个之内时：用核心声纹写作，问用户一句该平台的特殊要求，不要擅自套用相近平台文件。
2. **状态检查。** `status: 未初始化` → 走流程三。用户赶时间（"直接写，别折腾"）→ 只按 `rules.md` 基础规则写，交付时提醒一句"风格库还没提炼，这篇会偏中性"。
3. **收集输入。** 主题、素材、目标读者、篇幅。素材不足就问，问题一次性问完，不要挤牙膏。没有素材支撑的观点不硬写，宁可留白让用户补。
4. **大纲。** 篇幅 ≥1500 字或结构复杂时，先给大纲（候选标题 + 每节一句话要点）让用户确认；用户说"直接写"就跳过。
5. **派写作子 agent。** 用 Agent 工具派 general-purpose 子 agent，prompt 自包含，给全：风格库目录下 `voice.md`、`rules.md`、`platforms/<平台>.md` 的完整路径；文章根目录（来自 config.md）里同平台同题材定稿/旧文章的路径（让它先读一两篇找语感——模仿真文章比执行规则有效）；已确认的大纲、素材、篇幅；保存路径 `<文章根目录>/<YYYY-MM-DD-短slug>/draft.md`（用户指定了别处则听用户的）。明确要求：素材不足的地方标 `【待补：缺什么】`，不硬写、不编造；写完把文件存好，返回一段话摘要和待补清单。
6. **派审查子 agent。** 写作子 agent 返回后，派第二个子 agent。它只能拿到：draft.md 路径、`voice.md` / `rules.md` / 平台文件、`references/ai-tells-zh.md`。任务：以挑剔编辑身份对照检查表逐条过稿，命中就直接改文件（优先整句重写，不是只换词），优先级 **用户声纹 > 平台适配 > 检查表**；返回问题分类计数、典型修改前后例句、残留风险。红线：不透露任何写作过程信息。
7. **验收与交付。** 主 agent 读回改后的 draft.md 核对：文件存在、无 `【待补】` 遗留——有遗留就向用户要素材，让写作子 agent 补改标注处后再派一轮审查。然后输出正文全文，末尾附一句："改定后说「复盘这篇文章」并给我定稿，我会学习你的修改。"
8. **多平台分发。** 用户要发多个平台时，以过审核心稿为底，按各平台适配文件分别出变体、分开存文件；每个变体各派一次审查子 agent 过一遍再交付。

## 流程二：复盘学习（自进化核心）

触发：「复盘这篇文章」「复盘」「学一下这篇」。也接受单条意见（"以后别用XX词"），此时直接跳到第 3 步。

输入：初稿路径（流程一保存的 draft.md）+ 定稿（文件路径，或直接粘贴在对话里）。缺哪个就问哪个。

1. **逐段对比**初稿和定稿，把每处修改归类：删除 / 新增 / 改写 / 结构移动 / 事实纠正。
2. **判断可泛化性。** 检验标准一句话：**这条修改换一个话题还成立吗？**
   - 成立 → 候选规则（例：用户把所有"此外"都删了 → 规则：段落开头不用连接词）。
   - 不成立 → 不进风格库。若属于事实纠错，检查是否暴露了 AI 易错点（编数据、过度推断、虚构引用），是则在 `rules.md` 记一条事实纪律，防止下篇再犯。
3. **列候选规则给用户确认。** 每条带三样东西：证据（引用修改前后的原句）、归入位置（voice.md 声纹 / rules.md 硬规则 / platforms/*.md 平台习惯）、建议措辞。用户可删掉不要的。
4. **确认后写入。** 用 Edit 在对应文件的「学到的」区追加，规则末尾注明 `[YYYY-MM-DD ← 文章slug]`。
5. **定稿落盘。** 把用户给的定稿内容写成该文章目录下的 `final.md`（文章根目录来自 config.md）。它自动进入提炼语料。skill 里只住程序，风格库、文章、语料都住在项目里。
6. **一句话汇报**学到了什么，然后结束，不要展开啰嗦。

## 流程三：提炼 / 重新提炼（可重入）

触发：「提炼我的风格」（首次）、「重新提炼」「重新初始化风格」（重入）。两条口令走同一个流程——流程天然可重入：语料是扫描出来的，文章越攒越多，重跑一遍就是基于新范围重建画像。

1. **扫语料。** Read `config.md` 拿文章根目录，递归扫描其下所有 `.md` / `.txt`：`final.md`（复盘定稿）+ 任意位置的用户旧文章（含 `imported/`）。**排除 `draft*.md` 和 `README.md`**——AI 初稿和说明文档进了语料，等于把 AI 腔学成用户的风格，这是最严重的污染。默认全量；用户给了范围限定（"只用最近 10 篇""只用某日期之后的"）就按范围，并在结果里注明实际用了哪些。
2. 语料不足 3 篇也能做，但先说明样本少、画像会粗。
3. **逐篇分析**这些维度，边分析边记具体例子：
   - 句子：平均长度、长短交错模式、有无超短句
   - 段落：长度、一段一个意思还是爱挤一段
   - 开头：怎么起笔（场景？结论？提问？自嘲？）
   - 结尾：怎么收（戛然而止？观点收束？呼应开头？）
   - 口头禅与高频词（包括语气词、脏话、网络用语）
   - 标点：逗号切分节奏、破折号/省略号/问号频率、顿号习惯
   - 人称：第一人称密度、和读者说话的方式（"你""咱们""大家"）
   - 语气：正经/戏谑比例，自嘲、吐槽、发烧友式兴奋
   - 结构：小标题有无与风格、列表使用习惯
   - 论证：爱举例？爱讲亲身经历？爱给数据？
4. **产出草稿**：`voice.md` + 三个 `platforms/*.md`。各平台差异从该平台的样本文章里找；找不到就基于声纹给合理默认并标注"推测"。**重入时保留风格库全部「学到的」区**——复盘确认过的教训不因重炼丢失；保留项随草稿一并展示，过时的由用户在过目时手动删。
5. **给用户过目**，增删改后写入，`status` 更新为 `已初始化: YYYY-MM-DD，基于 N 篇样本，第 K 次提炼`（`run` 计数同步 +1）。
6. 攒了 5 篇以上新定稿时，主动建议用户「重新提炼」。

## 平台路由与协作

| 平台 | 读哪个文件 |
|------|-----------|
| 微信公众号 | `<风格库目录>/platforms/wechat.md` |
| 知乎 | `<风格库目录>/platforms/zhihu.md` |
| 掘金 / 博客 / V2EX 等 | `<风格库目录>/platforms/tech.md` |
| 其他 | 核心声纹 + 问用户一句平台要求 |

- 公众号排版（Markdown 转 HTML）：交给 `md-to-wechat`，本 skill 只出文字。
- 公众号全流程（选题→撰写→排版→草稿）：`wxmp-workflow` 主导时，本 skill 提供风格库供其撰写环节使用；文字风格上与本 skill 的风格库冲突时，以风格库为准。
